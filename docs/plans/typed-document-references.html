PLAN — Typed document references

dev board · task 69cd3660 (typed-document-references) · Draft v1 — awaiting plan_approved · spec →

Approach

Three separable tracks, deliberately ordered so the risky one is provably finished before anything irreversible happens to live data.

  1. The mechanism — a new field_schema type, its write-time validation, and the resolution check. Pure additive code; nothing existing changes behaviour.
  2. The surfaces — validate, two read routes, two inspector panels.
  3. The migrations and the deletion — dev off spec_doc, the template off its three fields, and the attachments/ scaffolding removed.

Track 3 is last because it touches live task state and the shipped template. Nothing there starts until track 1 is green: rewriting 7 tasks’ references onto a field type whose validator still has a hole would be the one genuinely hard thing to undo here.

The mechanism rides paths that already exist, which is what keeps this small:

  • src/substrate/field-validator.ts is called on every create_task/update_task with the exact touched_keys — so “refused at the point of writing” is one more checkType arm, not a new interception point.
  • assertPathUnder (src/http/middleware/path-canonical.ts) is written and tested and does exactly the containment check resolution needs. It survives the deletion of everything else attachment-shaped, and finally gets a second caller.
  • substrate.warnings: string[] already carries advisory diagnostics into substrate validate at exit 0.
  • custom_data is free-form JSON, so storage is zero work and zero migration.

Step-by-step work

Step 1 — The type and the write-time validator

  • src/core/types.ts: add 'document_refs' to FieldSchemaEntry.type, add roles?: string[], add the DocumentRef interface.
  • src/substrate/schemas.ts: extend the field-schema entry schema. Enforce “roles required and non-empty when type === 'document_refs'” the same way enum/ values is enforced today — find that rule and mirror it exactly rather than writing a second, differently-shaped one.
  • src/substrate/field-validator.ts: a new checkType arm delegating to a pure, separately-exported validateDocumentRefs(entry, value) covering every row of the spec’s enforcement table. Its errors keep the file’s existing message idiom — Field 'x' must be …, got …. Update custom_data.x and retry. — extended with the specific reason (“paths must be repo-relative; '/Users/…' is absolute”). A message that only says “invalid” fails the plan’s own requirement that the refusal say why.
  • Normalisation rule, decided once: compare on the POSIX form. Reject backslashes outright rather than translating them, so there is exactly one canonical representation on disk and no platform-dependent equality.
  • No filesystem access in this step at all. Assert it with a test that writes a reference to a nonexistent file and expects success (AC4).

Step 2 — Resolution

  • src/core/document-refs.ts (new): resolveDocumentRefs(repoRoot, refs) → { role, path, exists }[]. Join → resolve → assertPathUnder → existsSync. A path that fails containment is reported exists: false, never read — belt and braces behind the write-time check.
  • Repo root derivation in one helper next to it: repoRootFromSubstrateRoot(root) = dirname(root). Every caller uses it; nobody recomputes .. by hand.
  • A small collectDocumentRefs(board, task) that finds every document_refs-typed field on the board and pulls the matching custom_data values — so a board with two such fields works without special casing.

Step 3 — substrate validate

The step with the design decision in it (spec Q2).

  • After the existing policy-smell and member-warning loops, attempt the document check:
    • existsSync(p.dataSqlite) false ⇒ print Document references not checked (no database at <path>). and skip. This is the CI path — the DB is gitignored.
    • Present ⇒ openClient(p.dataSqlite) — not openDatabaseAndMigrate. A lint must never migrate a user’s data. Read user_version; if it is ahead of BINARY_SCHEMA_VERSION, skip with a message rather than erroring.
    • For each board, each active task, each document field: resolve; one warning per dangling reference, in the established format — Board 'dev' task 9a5af742 documents[spec] → docs/specs/x.html does not exist.
    • client.close() in finally. Warnings still exit 0.
  • Keep the whole block behind one guard clause so the DB-free path is obviously unchanged when reading the diff — that is the property a reviewer will want to verify at a glance.

Step 4 — Read surfaces

  • GET /api/tasks/:id/documents — resolved refs for one task. Follows the /api/tasks/:id/approval precedent: a small HTTP-only route with no MCP twin, because the agent reads its own task’s custom_data through get_task already.
  • GET /api/boards/:id/documents — every active task’s refs for that board, with ?group_id= and ?role= filters. Iteration is board-structure-driven (walk the board’s groups and its declared document fields), matching board-columns.ts’ contract of never trusting the DB to supply the key set.
  • Both routes need root to compute the repo root — and ApiDeps is Pick<ToolDeps, 'client' | 'config' | 'loadSubstrate'> specifically so the HTTP surface cannot reach the substrate-write root. Do not widen it. Instead pass a repoRoot: string through HttpConfig/ApiDeps — a read-only path string, not the writable substrate root. Say why in a comment; a future reader will otherwise “simplify” it back.
  • ui/src/lib/api.ts: two typed getters + the ResolvedDocumentRef type.
  • ui/src/routes/TaskDetail.tsx: a Documents section in the Details tab, above Custom data. Dead entries get a missing badge and are not hyperlinked; live ones are. Empty state: nothing rendered when the board declares no document field.
  • ui/src/routes/BoardDetail.tsx: a Documents panel with the group + role filters, dead entries marked.
  • Because documents stays in custom_data, TaskDetail would otherwise render the raw array twice — once in the new section, once in Custom data. Suppress the document-typed keys from the Custom data list.

Step 5 — Migrate the dev board

Data. Do it only once Steps 1–4 are green.

  1. Re-run the measurement from the spec and confirm 14/14 still resolve. If a link has rotted since, fix the file or empty the reference honestly — do not migrate a dead link into the new structure and launch the feature already failing its own check.
  2. Edit .substrate/boards/dev.json: add the documents field, remove spec_doc, update the gate-spec-build and resp-spec-authoring messages, bump version 10 → 11 and updated_at (this repo’s hand-edit convention — commit 00504e5 did the same).
  3. For each of the 7 tasks, one update_task writing documents and setting spec_doc: null in the same call. Both in one write, so no task is ever in a half-migrated state.
  4. Verify: substrate validate reports zero document warnings, and no task carries a spec_doc key.
  5. Update docs/README.md to describe roles instead of spec_doc.
These 7 writes are MCP writes against the live board, and they must run from the main checkout — .substrate/data.sqlite is gitignored and does not travel to a worktree, so the same commands from a worktree would silently open an empty board.

Step 6 — Migrate the web-delivery template

Risks & mitigations

Risk Mitigation
A path-validation hole ships, and 7 live tasks are migrated onto it. Absolute paths are precisely what the go-live exposure scrub exists to remove. Track ordering: no live data moves until Step 1 is green. Table-driven tests over every hostile form — /abs, ~/x, C:\x, a/../../b, ./a/../b (legal, normalises inside), https://…, a\b, '', a Unicode look-alike separator.
Widening ApiDeps to get a filesystem root, quietly undoing the “HTTP cannot reach the write path” invariant. Pass a distinct read-only repoRoot string; never add root. Comment it at the type. Flag it for reviewer (a) explicitly — it is the security-shaped change in this task.
validate stops being CI-friendly — the DB is gitignored, so a hard dependency would break it everywhere it currently runs. Presence-gated, openClient not openDatabaseAndMigrate, explicit skip line, exit 0 either way. AC7 tests the DB-absent path directly.
Half-migrated tasks — documents written but spec_doc left behind, so two sources of truth coexist. One update_task per task doing both; AC12 asserts no residual key on any of the 7.
Deleting path-canonical.ts by association while removing everything else attachment-shaped. Called out in the spec, in this plan, and in the PR body. It gains a caller in this very change.
Scope creep into URLs. “A PR link is the same shape” is the argument that would sink the feature, and someone will make it in review. Hard non-goal in the spec, with the reason (unverifiable) attached. The dev board’s existing pr string field is the standing answer.
The listing is the weakest item and could absorb disproportionate effort. Time-boxed to one route + one panel. If it slips, cut it: the plan says most of the value lands without it, and AC1–AC9 are unaffected.
Downstream drift — 9abed851’s evidence panel is specced against this shape. Both documents name the coupling. The resolution endpoint (GET /api/tasks/:id/documents) is the shared contract; if it changes, that spec is edited in the same PR.

Test strategy

Local gate only — CI is billing-blocked.

  • src/substrate/field-validator.test.ts — the hostile-path table above; an undeclared role; a non-array; a malformed element; a duplicate pair; a valid write; and the pure-function proof that a reference to a nonexistent file is accepted (AC4).
  • src/substrate/schemas.test.ts — a document_refs declaration without roles, and with roles: [], both rejected; with roles, accepted; every existing field type still parses (backward compat).
  • src/core/document-refs.test.ts — new. Present / absent / outside-root against a temp repo; collectDocumentRefs on a board with zero, one and two document fields.
  • src/cli/commands/validate.test.ts — dangling ref warns and exits 0; DB absent prints the skip line and exits 0; a DB whose user_version is ahead skips rather than errors; no migration is applied (assert user_version unchanged after the run — the property that makes openClient the right call).
  • src/http/routes/api/api.test.ts — both new routes: resolved flags, group and role filters, dead entries present and marked, 404 on an unknown task.
  • ui/src/routes/TaskDetail.test.tsx — live ref renders as a link, dead ref renders marked and not linked, document keys suppressed from Custom data, nothing rendered when the board declares no document field.
  • src/cli/commands/init.test.ts, src/shared/paths.test.ts — invert: assert no attachments/ directory and no gitignore line. path-canonical.test.ts untouched and still passing.
  • tests/integration/example-substrate.test.ts — the template’s parse-equal drift check with the new field.
  • Manual, once: after Step 5, rename one spec file, run substrate validate, see the warning naming task and role, rename it back. That is the whole feature in one gesture — and it is the thing that would have caught the three merged tasks.

Local gate before tests_green: pnpm build, tsc --noEmit at the root and in ui/, pnpm lint, pnpm format:check, pnpm test, plus substrate validate against the live .substrate/.

Rollout

  1. Branch off dev. One PR into dev.
  2. Commits in track order, so a reviewer can read the mechanism without the deletion noise: feat(fields): document_refs field type + resolution → feat(ui): document reference surfaces → chore(dev-board): migrate spec_doc to typed references → chore: remove the unbuilt attachments scaffolding.
  3. Two independent reviewers, distinct lenses. Suggested split: (a) correctness & security — the path validation table, the repoRoot-vs-root distinction, and whether validate can ever migrate or fail a load; (b) product & docs — is the posture really advisory everywhere, is the PRD honest after the rewrite, and did any URL-shaped scope sneak in.
  4. No database migration, so no data rollback exists or is needed. Reverting the code leaves documents arrays sitting harmlessly in custom_data as undeclared keys — which the validator accepts silently by design.
  5. Unblocks 9abed851. Say so on that task when this merges, and confirm that its evidence panel is built on GET /api/tasks/:id/documents rather than on spec_doc.
