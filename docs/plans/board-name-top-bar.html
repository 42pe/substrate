PLAN — Board name in top bar

dev board · task board-name-top-bar · Draft — awaiting plan_approved · spec →

Approach

All four routes render inside Layout's <Outlet/> (ui/src/main.tsx), and the persistent chrome is the Shell component in ui/src/routes/Layout.tsx. So the header is the single right place to surface identity. Add an AppHeader content block to Shell that shows the project name (always) and, when the current URL is a board or task route, the active board name.

The header derives the active board from the route with React Router's useMatch (unambiguous, works in the layout ancestor — no reliance on useParams bubbling), then fetches names with the app's existing per-component useResource hook (ui/src/lib/useResource.ts) over the typed client in ui/src/lib/api.ts. No new endpoint, no global store, no TanStack — consistent with how Overview/BoardDetail/TaskDetail already fetch. The board name is static per id and not polled (unlike columns), so a plain useResource is correct.

Recommended default (header-owned fetch, decoupled):

  • useMatch('/boards/:id') → have id → getBoard(id) → board.name.
  • useMatch('/tasks/:id') → getTask(id) → board_id → chained getBoard(board_id) → board.name (the acknowledged extra fetch on task detail).
  • Otherwise (Overview/Boards/Activity/unknown) → no board segment.
  • Project name: one useResource(() => getProject(), []) in the header.

This keeps the header fully self-contained and side-effect-free. It does duplicate getBoard on the board route (which BoardDetail also fetches) and getTask on the task route — see Risks for the reuse alternative, which is an open question for Diego.

Step-by-step work

  1. New hook ui/src/lib/useActiveBoard.ts: returns { name: string | null; id: string | null; loading: boolean }. Internally uses useMatch('/boards/:id') and useMatch('/tasks/:id'); for the board route calls getBoard(id); for the task route chains getTask(id) → getBoard(board_id). Returns nulls on non-board routes. Keeps all fetching logic testable in one place.
  2. New component ui/src/components/AppHeader.tsx (or an inline HeaderIdentity block if kept tiny): renders the project-name link (→ /) and, when useActiveBoard() yields a name, a separator + the board-name link (→ /boards/<id>). Uses the existing muted-foreground / <Link> styling vocabulary already in Shell. Truncation via Tailwind (truncate max-w-[…]) for narrow widths.
  3. Wire into Shell (ui/src/routes/Layout.tsx): insert the identity block into the existing <header> row, next to / replacing the bare Substrate wordmark line (exact layout per the spec's open question), leaving the primary <nav> and the ThemeToggle (in the ml-auto cluster) untouched. Do not touch LiveIndicator — it stays in page-body sections (Overview board wall, BoardDetail kanban), not the header.
  4. Project fetch: add getProject() via useResource in the header. Render the project segment only once resolved (or show the wordmark alone meanwhile) to avoid a flash.
  5. Graceful states: while the board name loads or if getBoard errors/404s, render nothing (or the chosen fallback) for the board segment — never surface an error card in the header. Reserve/allow space so the row doesn't jump (open question: skeleton vs. nothing).
  6. Tests (see Test strategy).
  7. Validate locally: build + tsc + lint + format + unit + smoke all green before moving Build → Review (CI is billing-blocked — validate locally per the repo's CI memory).

Risks

  • Extra board fetch on task detail. The default resolves the board via getTask → getBoard, duplicating TaskDetail's own getTask and adding a getBoard the page doesn't do today. These are cheap, same-origin, un-polled GETs, so acceptable. Alternative (open question): have BoardDetail/ TaskDetail publish the already-fetched board into a Layout-level context that the header reads — avoids the extra fetch but couples routes to the header and pushes state up via an effect (brief empty→filled flash on first paint).
  • Layout shift. The board segment appears after its async resolve, so the header can jump when the name lands. Mitigate by reserving space / a subtle skeleton, and by keeping the segment on one truncating line.
  • Crowding the header on narrow widths. The row already wraps (wordmark, nav, muted "read-only inspector" label, toggle). Adding project + board risks a cramped mobile bar. Mitigate with truncation and the mobile open question (truncate vs. hide below a breakpoint). Must not push or overlap anything.
  • Stale name across navigation. useMatch + useResource re-key on the route param, so the name refetches on nav; verify board→task→board and task→Overview clear/refresh correctly (covered by the component test).
  • StrictMode double-invoke (app runs in <StrictMode>): ensure the hook's chained fetch is guarded by useResource's active-flag pattern (it already ignores stale/unmounted resolutions).

Test strategy

  • Component tests (Vitest + Testing Library + MemoryRouter, mirroring ui/src/routes/BoardDetail.test.tsx's vi.mock('../lib/api.js') pattern): render the header inside a MemoryRouter at each route and assert —
    • /, /boards, /activity: project name shown (link to /); no board segment.
    • /boards/b1: board name (Roadmap) shown and links to /boards/b1; getBoard called with b1.
    • /tasks/t1: getTask → board_id → getBoard resolves the name; header shows the name, not the id.
    • Re-render at a different route updates/clears the board segment (no stale name).
    • Loading / getBoard-error path degrades to the chosen fallback without throwing.
  • Playwright smoke (tests/smoke/ui.spec.ts, real built stack over the seeded .substrate/): extend the existing board detail case (/boards/main) and task detail case (/tasks/t1) to assert the header shows the board name Roadmap (scoped to <header> so it doesn't collide with the page <h1> or the boards list), and that Overview/Boards/Activity headers show no board segment. Keep the existing zero-console-error assertion.
  • Local gate: build + tsc + lint + format + unit + smoke all green locally before Build → Review (sets tests_green); CI is billing-blocked, so local is the source of truth.
