Approach

This is a small, additive, dependency-free tool. The whole feature is a pure function that maps { title, body, agent_name? } to a prefilled GitHub issues/new URL, wrapped in the same tool scaffolding as whoami and reverse_captcha. No storage, no network, no event, no new dependency (URL assembly uses the built-in URL/URLSearchParams or encodeURIComponent). Because it touches nothing stateful, the risk surface is the string assembly itself: correct encoding, the title prefix, and the version stamp.

The handler is exported separately from the register… function so the unit test calls the pure handler directly (no MCP server, no stdio) — matching how reverseCaptchaHandler is tested. BINARY_VERSION is imported from src/core/version.ts so the version stamp can never drift.

Handler sketch (illustrative, not final code)

export const REPO = '42pe/substrate';
const TITLE_PREFIX = 'Substrate Feedback: ';

export function submitFeedbackHandler(input: SubmitFeedbackInput): SubmitFeedbackResult {
  const issue_title = TITLE_PREFIX + input.title;
  const footerLines = [`Filed via Substrate v${BINARY_VERSION}`];
  if (input.agent_name) footerLines.push(`Agent: ${input.agent_name}`);
  const body = `${input.body}\n\n---\n${footerLines.join('\n')}`;
  const params = new URLSearchParams({ title: issue_title, body, labels: 'feedback' });
  const url = `https://github.com/${REPO}/issues/new?${params.toString()}`;
  return {
    result: 'feedback_url',
    url,
    issue_title,
    repo: REPO,
    instructions:
      "Open this URL in a browser and click 'Submit new issue' to file it. Nothing was sent automatically.",
  };
}

Note: URLSearchParams encodes spaces as + in the query string, which GitHub decodes correctly; if the tests prefer %20, swap to explicit encodeURIComponent concatenation. Either is acceptable — the acceptance test asserts round-trip via decode, not the exact escape byte, to avoid brittleness.

Risks

  • URL length under percent-encoding. A 4096-char body of high-entropy or multibyte content can inflate past GitHub's ~8 KB prefill guideline. Mitigation: schema caps bound the input; typical ASCII feedback stays well under. Accepted for v1; if it bites, follow up with a lower body cap or an output-side length guard that returns a distinct result variant. Documented, not silently truncated.
  • feedback label may not exist. Mitigation: one-time maintainer step to create it (resolved question 2). Absence is a cosmetic GitHub banner, not a failure, so the tool is robust either way; the title prefix is the always-present tag.
  • Encoding correctness. Ampersands, hashes, and newlines in body/title must not break the query string. Mitigation: use URLSearchParams/encodeURIComponent (never manual concatenation) and assert round-trip decode in tests.
  • Version-stamp drift. Mitigation: import BINARY_VERSION; the test asserts the footer contains the imported value, not a literal — mirroring the whoami phase-string discipline.
  • Scope creep. category, environment capture, and API submission are explicit non-goals; the reviewer should reject any of them sneaking in.

Test strategy

Test the pure handler directly (no server, no stdio, no network) plus the one integration assertion on the tool surface. Deterministic — no Date.now/network to stub.

  • Happy path. Given a title and body, assert result === 'feedback_url', repo === '42pe/substrate', issue_title === 'Substrate Feedback: ' + title, and that url starts with https://github.com/42pe/substrate/issues/new? and contains labels=feedback.
  • Encoding round-trip. Parse url with new URL(); assert searchParams.get('title') equals the prefixed title and searchParams.get('body') equals the composed body — using a body containing &, #, and newlines to prove escaping.
  • Version stamp. Assert the decoded body contains `Substrate v${BINARY_VERSION}` (import the constant into the test, don't hardcode).
  • Attribution. With agent_name, the decoded body footer contains Agent: <name>; without it, the body contains no Agent: line.
  • Schema caps. Parsing the schema with a 121-char title, a 4097-char body, or an empty title/body fails (schema.safeParse(...).success === false) — proving wrapToolHandler would emit schema_violation rather than a URL.
  • No ok field. Assert the result object has no ok key (so the wrapper reports isError: false), matching whoami/reverse_captcha.
  • Surface test. The updated mcp-bootstrap-flow.test.ts assertion lists 32 tools including submit_feedback, and (optionally) a tools/call smoke test returns a non-error envelope with a github.com URL.
