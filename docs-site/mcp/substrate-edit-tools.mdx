These twelve tools edit substrate-as-code, the same thing you could edit by hand in
`.substrate/boards/<id>.json`. Changes take effect on the next read: no migration, no
restart.

All require `agent_name`; all updates and archives require the current `version`.

<Tip>
  Reach for these to **extend** an existing board. Creating a second board that models the
  same flow is the most common way a substrate stops being a single source of truth.
</Tip>

<ParamField path="name" type="string" required />

<ParamField path="description" type="string" />
<ParamField path="field_schema" type="object">Optional; validated structurally.</ParamField>

### `update_board`

<ParamField path="id" type="string" required />
<ParamField path="version" type="integer" required />
<ParamField path="agent_name" type="string" required />
<ParamField path="name" type="string" />
<ParamField path="description" type="string" />
<ParamField path="field_schema" type="object">Replaces the whole schema.</ParamField>
<ParamField path="field_schema_patch" type="object">Merges; `null` deletes a field.</ParamField>

Schema changes **never reject existing data** — validation is lazy. To change one field,
prefer `field_schema_patch` over resending everything.

<Warning>
  `update_board` refuses to **downgrade** a `human_only` field — an agent can neither clear
  the flag nor delete the field to escape a human gate.
</Warning>

## Policies

### `create_policy`

<ParamField path="board_id" type="string" required />
<ParamField path="name" type="string" required />
<ParamField path="type" type="'transition_guard' | 'agent_responsibility'" required />
<ParamField path="definition" type="object" required>Validated against `type`.</ParamField>
<ParamField path="agent_name" type="string" required />
<ParamField path="description" type="string" />
<ParamField path="priority" type="integer" />
<ParamField path="enabled" type="boolean" />

The definition shapes:

- **`transition_guard`** → `{ from_group, to_group, require?, on_failure_message? }`.
  Blocks a matching move unless every `require` condition passes. `from_group` and
  `to_group` are group ids, or `"*"` for any.
- **`agent_responsibility`** → `{ when?, message }`. Never blocks; attaches `message` as a
  suggestion in the write envelope when `when` matches. An empty `when` always matches.

Conditions are `{ field, op, value?, values? }` or a compound
`{ all_of | any_of | none_of: Condition[] }`. Fields resolve literal-then-`custom_data`,
so a gate field is `task.<name>`. Full grammar: [write policies](/authoring/write-policies).

<ParamField path="id" type="string" required />

<Warning>
  Archiving a guard removes a rail. It is git-visible and event-logged rather than silent —
  but an agent under pressure archiving the gate that blocks it is the residual risk in
  the model. See [what a gate guarantees](/concepts/policies-and-gates#what-a-gate-actually-guarantees).
</Warning>
