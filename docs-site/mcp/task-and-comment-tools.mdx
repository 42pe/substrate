Every tool here requires `agent_name`. Task writes require the `version` from your last
read; comment writes do not.

### `update_task`

<ParamField path="id" type="string" required />
<ParamField path="version" type="integer" required>From your last read. Stale → `version_mismatch`.</ParamField>
<ParamField path="agent_name" type="string" required />
<ParamField path="title" type="string" />

<ParamField path="custom_data" type="object">**Merges key-by-key**; `null` deletes a key.</ParamField>

Send only the fields you are changing.

A blocked move returns `transition_blocked` and appends a `move_blocked` event to the
task's history. Read the message, satisfy the requirement, retry.

### `archive_task` / `unarchive_task`

<ParamField path="id" type="string" required />
<ParamField path="version" type="integer" required />

Soft delete and restore. `archived_at` is set or cleared; history is preserved. Nothing
hard-deletes a task.

## Fields or comments?

Put in a **field** anything a policy must read, anything you will filter on, and anything
that represents state. Put in a **comment** the reasoning: why this approach, what was
rejected, what the next session needs to know. Nothing reads prose.
