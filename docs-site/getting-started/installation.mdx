## Requirements

| | |
| --- | --- |
| **Node.js** | 20 or newer |
| **macOS / Linux** | Primary. Developed and tested here. |
| **Windows** | Best-effort; WSL is the recommended path. |

Substrate stores everything in a `.substrate/` directory inside your project. There is
nothing to sign up for and nothing to configure globally.

## Install

<Warning>
  **v0.7.0 is pre-release.** Substrate is not published to npm yet, so
  `npx @diegoferreyra/substrate` does not resolve. Until it ships, install from a local
  clone as below — the `substrate` command then behaves identically everywhere.
</Warning>

<Steps>
  <Step title="Clone and build">
    ```sh
    git clone https://github.com/42pe/substrate.git
    cd substrate
    pnpm install
    pnpm build
    ```
  </Step>
  <Step title="Link the binary globally">
    ```sh
    pnpm link --global
    ```
    This puts `substrate` on your `PATH`. Once the package is on npm this step goes
    away and every command below can be run as
    `npx @diegoferreyra/substrate <command>`.
  </Step>
  <Step title="Install the agent skill">
    ```sh
    substrate install-skill
    ```
    Copies the packaged agent skill into `~/.claude/skills/substrate`, stamped with the
    binary's version so the two cannot silently drift. See
    [`substrate install-skill`](/cli/install-skill).
  </Step>
</Steps>

## Verify

```sh
substrate --help
```

The help output opens with the version it was built from — `Substrate v0.7.0 — …`.
There is no `--version` flag in v0.7.0.

Inside a project that already has a `.substrate/`, the fuller check is:

```sh
substrate diagnose
```

It prints environment and substrate health and exits non-zero if it finds a problem.
Every probe is wrapped, so it still produces a useful report when the substrate itself
is broken. See [`substrate diagnose`](/cli/diagnose).
