# UX review — the read-only web inspector, before interactivity — 2026-06-29

**Status:** Review complete → seeds [Phase 12 — UX foundation](plans/phase-12-ux-foundation.md)
**Method:** A four-lens reviewer team (visual design · interaction/IA · accessibility ·
frontend/design-system) audited the **real rendered UI** — screenshots captured from a
production `build:ui` served over a seeded `.substrate/` (Overview, Boards, Board kanban,
Board list, Task detail, Activity, + mobile + comments), cross-checked against
`ui/src/` source with file:line evidence.
**Why now:** Diego asked to fix the UI **before** adding write-interactivity
([interactive-ui-spec.md](plans/specs/interactive-ui-spec.md)), so the interactive layer
lands on a solid, accessible, tokenized base instead of multiplying today's gaps.

---

## Verdict

The UI is **clean, type-safe, and has genuinely good data-layer discipline** (token-aware
polling with cancellation, `allSettled` isolation, no loading-flash on background ticks).
But it is **not built on a design system** — it's raw Tailwind `neutral-*` utilities inlined
into JSX (118 hardcoded `neutral-*` refs, **0** semantic tokens, **0** `dark:` classes), it
**fails several WCAG 2.1 AA criteria**, and the primitives the interactivity phases need
(Button/Input/Dialog/Select/Toast, a mutation hook, a status/conflict channel) **don't
exist yet**. The fixes are foundational and best done once, before interactivity.

## Top cross-cutting fixes (do first)

1. **Install a semantic token layer** in `styles.css` `@theme` (+ `:root`/`.dark`) and
   refactor the 4 vendored primitives to consume it. Unblocks restyle, dark mode, and
   every new primitive. *(frontend P0-1/2/3, visual)*
2. **Establish an accessibility floor** — a global `focus-visible` ring (none exist today;
   `Tabs.tsx:32` actively removes outlines), fix muted-text contrast (`neutral-400` ≈
   **2.6:1** fails 1.4.3), fix status-dot contrast (`emerald-400`/`amber-400` ≈ 1.6–1.8:1)
   + don't encode status by color alone, and tame the `aria-live` spam. *(a11y P0-1..4, P1-1)*
3. **Hoist a single canonical status/conflict channel** into the header. Liveness is
   fragmented today (no indicator on Boards, Task detail, or the List view) and
   `reconnecting`/`paused` are too quiet to function as alarms. This same slot becomes the
   "an agent changed this while you edited" conflict surface in interactivity. *(IA P0-1/2)*
4. **Vendor the missing primitives + a mutation/status scaffolding** (Button, Input,
   Textarea, Label, Select, Dialog, Toast, DropdownMenu, Checkbox; `apiPost/apiPatch`,
   `useMutation`, `refetch()` on the polling hooks, optimistic `setData` + a generation
   guard, an app-level announcer). *(frontend P0-4/P1-1, a11y scaffolding)*
5. **Unify the obvious inconsistencies** — date formatting (relative everywhere, raw
   `toLocaleString` reads like debug output), the raw-board-ID breadcrumb, deduped
   PageHeader/TaskCard/LoadMore, and URL-addressable tabs/filters. *(all four lenses)*

## Findings by theme (deduped, P0 / P1 / P2)

### A. Design-system foundation
- **P0 — No token layer; theme is raw Tailwind palette.** `styles.css` defines only
  `--animate-card-pulse`; 118 hardcoded `neutral-*` (+ `red/amber/emerald/white`) across
  ~30 files. *Fix:* `@theme` + `:root`/`.dark` with the ShadCN set (`--background,
  --foreground, --card, --muted(-foreground), --border, --input, --ring, --primary(-fg),
  --destructive(-fg), --warning, --accent, --radius`).
- **P0 — Dark mode structurally impossible.** `grep dark:` → 0; `@custom-variant dark`
  commented out (`styles.css:9`); `index.html:8` hardcodes `bg-neutral-50 text-neutral-900`.
  *Fix:* enable the variant, drive `<body>` from tokens; near-free once primitives tokenize.
- **P0 — Vendored primitives hardcode palette.** `Card.tsx:7,22`, `Badge.tsx:10-14`,
  `Table.tsx:13,23,33`, `Tabs.tsx:11,23`. *Fix:* rewrite to `bg-card/border-border/
  text-muted-foreground/bg-muted/text-destructive`.
- **P0 — Missing interactive primitives.** Only Card/Badge/Tabs/Table exist; buttons/
  inputs/selects are ad-hoc inline JSX (raw `<button>` ×4: `BoardDetail.tsx:271,321`,
  `TaskDetail.tsx:134,177`; raw `<select>` `BoardDetail.tsx:237`; raw checkbox/search
  `BoardDetail.tsx:250,264`, `Boards.tsx:28`). *Fix:* vendor ShadCN-style (CVA + `cn`,
  Radix where applicable — Radix already a dep) Button/Input/Textarea/Label/Checkbox/
  Select/Dialog/DropdownMenu + `sonner` Toast.
- **P1 — Duplicated composite markup.** PageHeader block repeats across all 5 routes; the
  "Load more" button is identical ×3 (`BoardDetail.tsx:320`, `TaskDetail.tsx:133,176`);
  the kanban card is near-duplicated between `Kanban.tsx:50` and `Overview.tsx` MiniColumn.
  *Fix:* extract `PageHeader`, `SectionHeading`, `LoadMoreButton`, a shared `TaskCard`, and
  a `SegmentedControl` (the bespoke `ViewToggle` `BoardDetail.tsx:63` re-implements Tabs).
- **P2 — `prose`/`prose-sm` classes are no-ops** (`@tailwindcss/typography` not installed):
  markdown descriptions render unstyled (`Overview.tsx:29`, `BoardDetail.tsx:105`,
  `TaskDetail.tsx:61`). *Fix:* add the plugin or a tokenized `.markdown` style — decide
  before comment-rendering (Phase 14) lands.
- **P2 — Spacing rhythm varies** route-to-route (`space-y-8/6/5/4`). *Fix:* a small scale
  convention applied via the shared primitives.

### B. Accessibility (WCAG 2.1 AA)
- **P0 — No visible focus indicator** (2.4.7). Zero focus styles in `styles.css`;
  `Tabs.tsx:32` adds `focus:outline-none` with no replacement; cards-as-links, the toggle,
  the `<summary>`, Load-more, nav all lack a ring. *Fix:* one global `:focus-visible` ring
  token applied to all interactive elements.
- **P0 — Muted text below 4.5:1** (1.4.3). `text-neutral-400` (#a1a1aa) ≈ **2.6:1** on
  white — the app's most common metadata ("updated … ago" `Kanban.tsx:59`, "read-only
  inspector" `Layout.tsx:30`, board ids, required labels, empty states). `neutral-500` on
  the `neutral-50` shell ≈ **4.48:1** (borderline, section labels). *Fix:* ban
  `neutral-400`-on-white for text; promote to `neutral-600`; muted-on-shell → `neutral-600`.
- **P0 — Status dots fail non-text contrast + color-only** (1.4.11, 1.4.1).
  `LiveIndicator.tsx:30-36` `emerald-400`≈1.8:1 / `amber-400`≈1.6:1; live-vs-reconnecting is
  hue-only. *Fix:* `emerald-600/amber-600` + a shape/glyph difference, keep the text label.
- **P1 — `aria-live` spam** (4.1.3). `LiveIndicator.tsx:40` wraps text that re-renders every
  1000ms → SR announces a new "updated N seconds ago" forever. *Fix:* announce only state
  *transitions*; exclude the ticking timestamp from the live region.
- **P1 — Kanban is `<div>`s, not lists; counts have no unit** (1.3.1). `Kanban.tsx:75,83`;
  badge `Kanban.tsx:81` reads "To do 1". *Fix:* columns → `role="list"`/`<li>` with
  per-column `aria-label`; `sr-only` unit on counts (no `sr-only` utility exists — add it).
  **This list structure is a prerequisite for accessible drag-and-drop.**
- **P1 — Touch targets < 24/44px** (2.5.8): Board/List toggle (`py-1`), nav (`px-2 py-1`),
  "+N more". **P1 — heading gaps** on the Overview wall (board names not headings).
  **P1 — no skip-link / unlabelled `<nav>`** (`Layout.tsx`).
- **P2 — reduced-motion** not honored for the pulses (2.3.3); search input lacks a label
  (3.3.2); `<pre>` JSON event dumps need `tabindex=0` for keyboard scroll.

### C. Status, liveness & conflict (interaction/IA)
- **P0 — Liveness fragmented & partly invisible.** Indicator only on Overview/BoardDetail-
  kanban/Activity; **none** on Boards, Task detail, or the List view — a frozen snapshot
  with no signal it's frozen (a correctness hazard once agents write concurrently).
  *Fix:* one header-level freshness indicator driven by a shared heartbeat.
- **P0 — `reconnecting`/`paused` too quiet.** A 5-min-dead board looks live except a tiny
  dot (`usePolling.ts:86` never escalates). *Fix:* escalate with dwell time ("last live
  3m ago" / dim stale content). **This is the same channel reused for edit-conflict
  messaging in interactivity — build the prominent status slot now.**
- **P1 — Moved-card pulse is ephemeral** (`Kanban.tsx:22-45`): one-shot, kanban-only; look
  away and "what changed" is gone. *Fix:* a persistent "recently changed" marker + a
  board-level "N updates since you arrived" (also the home for optimistic/conflict state).
- **P1 — No "what needs me?" roll-up.** `missing_required_fields`/`move_blocked` exist per
  card but there's no board- or overview-level count; the status the human needs is buried
  in the collapsed "Board details" disclosure (`BoardDetail.tsx:91`).

### D. Wayfinding & consistency
- **P0 — Breadcrumb is a raw board ID.** `TaskDetail.tsx:33` `← {task.board_id}` renders a
  UUID on any real board. *Fix:* `← {board.name}`, ideally a full `Boards / Board / Task`
  breadcrumb.
- **P1 — Tabs/disclosure/filters not URL-addressable** (`TaskDetail.tsx:46` defaultValue;
  native `<details>`), while the board view *is* (`?view=list`). Breaks deep-linking to
  Comments/Events and post-action redirects. *Fix:* move tab/disclosure/filter state to
  search params.
- **P1 — Two different board renderings** (Overview MiniColumn `w-56`/limit 4/overflow→board
  vs Kanban `w-72`/overflow→list); the missing-required badge is absent from the Overview
  glance. *Fix:* one shared column/card primitive with density variants; carry the badge.
- **P1 — Events tab dumps raw JSON** (`TaskDetail.tsx:167`, `JSON.stringify`). *Fix:*
  field-level diffs ("group: To do → Done"), shared humanizer with Activity.
- **P1/P2 — date formatting inconsistent** (raw `toLocaleString` vs `timeAgo`) — unify on a
  `<RelativeTime title=absolute>` helper.

### E. Visual & layout
- **P1 — Vast top-loaded whitespace.** Every page crams content at the top with a large
  blank expanse below (screenshots 03/05); the kanban reads as unfinished. *Fix:* let
  columns fill viewport height / ground the layout; tighten the max-width story.
- **P1 — Mobile header overflow.** At 390px the wordmark + nav + "read-only inspector"
  tagline don't fit; the tagline clips off-screen (screenshots 07/08); no responsive nav.
  *Fix:* responsive header (hide tagline < sm, collapse nav), reflow check at 320px (1.4.10).
- **P2 — Over-bordered, low-depth treatment** (tiny content in big bordered near-white cards)
  and **minimal brand** (plain wordmark, single green accent). Keep it minimal, but a token
  accent + slightly stronger hierarchy raise perceived quality.

## Interactivity-readiness — scaffolding to pre-build (the point of Phase 12)

Build these so drag, dialogs, forms, and comments drop in cleanly:

1. **Token layer + dark-mode structure** (§A) — the base everything else consumes.
2. **Accessibility floor** (§B) — global focus-visible ring, `sr-only` utility +
   `<VisuallyHidden>`, reduced-motion gate, contrast-safe semantic text tokens.
3. **One app-level announcer** — a single polite `role="status"` region (+ an assertive one
   for errors) mounted in `Layout`, with `useAnnounce()`. Reused for "Task moved to Done",
   "Comment posted", "Move blocked by policy", "changed underneath you". Fixes the
   LiveIndicator spam in the same stroke.
4. **Canonical header status/conflict channel** (§C) — prominent, route-level; today shows
   live/reconnecting/paused, tomorrow shows edit-conflicts.
5. **Semantic board structure** — columns as `role="list"`/`<li>` with `aria-label`; the
   prerequisite for keyboard-accessible DnD.
6. **Keyboard-drag contract (design now)** — per-card "Move to…" affordance,
   `aria-roledescription`, Space-grab / arrows / Enter-drop / Esc-cancel, announced via the
   live region. Pointer-only drag without this is a 2.1.1 failure.
7. **Dialog/focus-trap primitive** (Radix Dialog) and a **Field** primitive (label +
   control + `aria-describedby` error association) — every future form inherits correct
   focus + error semantics.
8. **Mutation/optimistic data layer** — `apiPost/apiPatch/apiDelete` (mirror `apiGet`'s
   `ApiError`); `useMutation` → `{mutate,isPending,error,reset}`; expose `refetch()` from
   `usePolling`/`usePaginated` + an optimistic `setData` with a **generation guard** so a
   4s poll tick can't clobber an in-flight optimistic move; a `useToast` bridge.
9. **URL as view-state** — tabs/filters/disclosure/selected-board addressable, enabling
   deep-links, post-action redirects ("created → open it"), and conflict recovery.
10. **Shared primitives/dedup** — PageHeader, SectionHeading, LoadMoreButton, TaskCard,
    SegmentedControl; unify date formatting; fix the breadcrumb.

### Affordance-placement map (where each future write control lands)
| Write action | Home | Pre-build in Phase 12 |
|---|---|---|
| Move a card (drag) | `KanbanCard`/`KanbanColumn` | drag handle vs click-to-open separation; list semantics; persisted "moved" signal |
| New task | column header + board-level button by `ViewToggle` | empty header action slot on `KanbanColumn` (knows its `group_id`) |
| Edit / archive task | `TaskDetail` header action row | right-aligned action area; URL-addressable tabs |
| Add / edit comment | bottom of Comments tab + per-comment Reply | composer slot; visible parent context; URL-addressable tab |
| Add / rename / reorder column | trailing "+" column + column header menu | shared column primitive with a header action slot |
| New / edit board, manage policies | Boards header + the Board-details disclosure | inline policy/schema summary as the anchor |

## DnD recommendation
**`@dnd-kit`** — headless (style overlays with our own tokens), first-class keyboard +
screen-reader sensors, tiny tree-shakeable core, solid React 19 story; preferred over
`@hello-pangea/dnd` (heavier, opinionated, shakier under React 19 strict mode). Matches
spec decision **D5**.

## Sequencing
Phase 12 (UX foundation) is small-to-medium and **improves the read-only v1 inspector
itself**, so it can ship **before public launch** as polish, with interactivity (13–15) as
v1.1 — or all post-launch. See interactive-ui-spec §9 Q1.
